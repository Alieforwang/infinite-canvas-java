## 0. 已确认的产品方向（用户决策）

1. **形态**：从参考项目的「本地单人工具」升级为「平台」——用户注册登录、管理员在后台配置模型、用户充值积分或购买套餐后按量计费使用。
2. **保留功能**：无限画布、视频创作台、我的资产/生成记录；其余无关功能删除（生图工作台、提示词库、画布助手 Agent、插件系统等）。
3. **技术栈**：Java 17 + Spring Boot + MySQL；前端沿用参考项目的 Web 技术栈。
4. **接入方式**：管理员配置「支持 OpenAI 接口协议」的视频模型服务（Base URL + API Key + 模型），平台后端统一代理、统一计费、统一存储。

## 1. 背景与机会

### 1.1 背景

参考项目 `infinite-canvas` 是一个本地优先的 AI 图片/视频创作画布：前端直连用户自己填写的 OpenAI 兼容接口，API Key 存在浏览器里，画布、素材、生成记录全部存在浏览器 IndexedDB。它证明了「无限画布 + 节点式生成」的创作体验成立，但作为产品存在三个结构性缺口：

1. **用户门槛高**：需要自备 Base URL、API Key、模型名，普通创作者无法开箱即用。
2. **数据不落地**：画布、素材、记录只在本机浏览器，换设备/清缓存即丢失，无法做多端和团队场景。
3. **无法商业化**：没有账号体系、没有计费、没有运营后台，API Key 暴露在前端也有安全风险。

### 1.2 机会

视频模型（Sora 2、Veo、Kling、Seedance、Wan、Hailuo 等）正通过大量「OpenAI 兼容」聚合站/中转站提供统一接入。把这些能力收口到平台后端，可以做成一款**面向视频创作的开箱即用工作台**：平台统一采购/配置模型，用户按积分付费，创作资产沉淀在云端。

### 1.3 产品目标（本期）

| 目标 | 衡量方式 |
|---|---|
| 跑通「注册 → 充值 → 生成视频 → 扣费 → 下载/沉淀资产」闭环 | 端到端验收清单全部通过 |
| 用户无需接触 API Key 即可生成视频 | 新用户 5 分钟内完成第一条视频 |
| 画布创作成果可沉淀 | 画布项目与资产云端保存，换浏览器仍可见 |
| 管理员可独立运营模型与价格 | 后台改模型价格后，新任务立即按新价计费 |

**非目标（本期不做）**：图片生成、提示词库、AI 对话/Agent、插件生态、团队协作/共享画布、移动端深度适配、在线支付自动到账、内容审核系统。

## 2. 产品定位与价值主张

> **一句话**：把「无限画布」的节点式创作体验，做成普通人也能用的视频生成工作台——模型平台配、额度按积分算、作品存云端。

| 角色 | 痛点 | 平台给的价值 |
|---|---|---|
| 短视频创作者 | 多个模型平台来回切换、充值分散、成片管理混乱 | 一个入口统一模型、统一余额、统一作品库 |
| 设计师/广告从业者 | 需要反复调参数、用参考图控镜头 | 视频创作台快速出片 + 画布串联「提示词→参考图→多镜头」 |
| 小型工作室 | 成员各自买 Key、成本不可控 | 管理员统一配置与定价、按人计费、后台看用量 |
| 平台运营方（管理员） | 想接入/替换模型供应商、调价、控成本 | 渠道+模型+定价后台配置，无需发版 |

**差异化**：不是又一个「模型聚合对话框」，而是**画布编排 + 异步任务 + 云端资产**的工作台；模型是耗材，创作上下文（画布、参数、参考图、历史）才是留存。

## 6. 核心用户旅程

### 6.1 新用户首次生成（Happy Path）

1. 打开首页 → 注册（邮箱+密码）→ 自动登录 → 顶部与账户页显示赠送积分（默认 100）。
2. 进入「视频创作台」→ 选择模型（默认第一个上架模型，显示「积分/秒」）→ 输入提示词 → 选时长/比例/分辨率 → 看到预估费用。
3. 点击「开始生成」→ 余额校验/预扣 → 任务进入「排队中」→「生成中（进度 %）」。
4. 生成完成 → 播放、下载、保存到「我的资产」→ 积分流水出现一笔消费。
5. 在「我的账户」看到余额与流水；在「我的资产」看到视频。

### 6.2 画布连续创作

1. 「无限画布」→ 新建项目 → 文本节点写分镜提示词 → 图片节点上传参考图 → 连线到「生成配置节点」。
2. 配置节点选模型/时长/比例/分辨率 → 生成 → 节点显示进度 → 成片以视频节点插入并自动连线。
3. 基于成片抽「尾帧」作为下一镜头的首帧参考 → 继续生成 → 刷新/换设备后项目与任务状态仍在。

### 6.3 管理员配置模型

1. 管理员登录 → 「渠道管理」新增渠道（Base URL、API Key、协议档位）→ 连通性测试。
2. 「模型管理」从上游拉取或用「上游模型名」新增模型 → 配置参数能力（时长/尺寸/分辨率/参考图/首尾帧）与积分定价 → 上架。
3. 用户端刷新后模型下拉出现新模型；新任务按新价格预扣。

### 6.4 失败与退款

1. 任务因上游失败/超时/风控失败 → 用户看到明确原因与「重试」。
2. 系统自动全额退回预扣积分 → 流水出现「退款」；管理后台任务详情可看到上游错误与 request id。

## 9. 计费规则详述

### 9.1 账户模型

| 字段 | 含义 |
|---|---|
| `available` | 可用积分（生成预扣时减少） |
| `frozen` | 冻结积分（进行中任务的预扣） |
| `consumed` | 累计消耗（成功任务结算后增加） |
| 流水 | 每次余额变动写一条不可变记录（类型、数量、余额快照、关联任务/订单、操作人） |

### 9.2 定价公式

```
任务费用 = ceil( 模型积分/秒(480p 基准) × 分辨率系数 × 音频系数(可选) × 时长(秒) )
最低 1 积分；分辨率系数按模型配置（默认 480p=1.0、720p=1.5、1080p=2.0，可改）
```

示例（占位定价，管理员可改）：

| 模型 | 积分/秒（480p 基准） | 6 秒 720p（×1.5） | 8 秒 1080p（×2.0） |
|---|---|---|---|
| sora-2（示例） | 10 | 90 | 160 |
| veo-3（示例） | 16 | 144 | 256 |
| seedance（示例） | 6 | 54 | 96 |

### 9.3 扣费生命周期

1. **创建任务**：校验余额 ≥ 费用、并发未超限 → 同一事务内 `available -= fee`、`frozen += fee`、写 `HOLD` 流水、创建任务（状态 `QUEUED`）。
2. **成功**：`frozen -= fee`、`consumed += fee`、写 `SETTLE` 流水、任务置 `SUCCEEDED`。
3. **失败/超时/取消/下载失败**：`frozen -= fee`、`available += fee`、写 `REFUND` 流水、任务置 `FAILED/CANCELLED`。
4. **管理员重试**：对已失败任务生成新任务，并按当前价格重新预扣（原任务失败时已自动全额退款）；进行中任务不可重试。
5. **幂等**：同一任务只允许一次终态资金操作；以任务状态机 + 流水幂等键（`finalize:{taskNo}`，SETTLE 与 REFUND 共用唯一索引，物理互斥）保证。

### 9.4 其他规则

- 余额不足：提示「还差 X 积分」并跳转账户页。
- 并发限制：进行中（QUEUED/RUNNING）任务数 ≥ 上限时拦截，提示等待或取消其他任务。
- 兑换码与手工充值：仅增加 `available` 并写流水；不产生冻结。
- 管理员调账：必须填写原因，写流水与审计。
- 注册赠送：注册事务内发放，金额取系统设置（默认 100）。
- 套餐（P0）：记录套餐、有效期、额度，本期不做自动续费/到期扣减逻辑；套餐积分直接入 `available` 并写流水。
